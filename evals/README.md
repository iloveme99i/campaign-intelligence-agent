# Agent 评测集

`merchant_review_cases.jsonl` 是一组可执行的 54 场景矩阵，不预填模型文案。它覆盖 3 类跨业务活动、4 种决策意图、4 类风险重点，以及带渠道、方案、人群和经营点限制的过滤口径。每条场景固定任务、口径、允许的诊断方向、必答主题和验收状态。

重新生成并验证矩阵（不调用模型）：

```bash
.venv/bin/python scripts/build-merchant-eval-cases.py
.venv/bin/python scripts/run-merchant-eval-suite.py
```

配置真实 DeepSeek API 后，显式执行场景；该命令会消耗模型额度，因此默认不会自动运行：

```bash
.venv/bin/python scripts/run-merchant-eval-suite.py --execute
```

runner 会创建隔离会话、执行 Agent、读取持久化 trace、核对工具顺序与诊断方向、运行 `score_trace`，并把失败模式写入 `evals/latest-suite-run.json`。报告同时保留模型配置、场景覆盖、断言失败分布、质控失败分布、修复重试率、Token 消耗和时延分位数。评测会话默认全部清理，不污染真实用户的会话列表；调试时可用 `--keep-failures` 只保留失败会话，或用 `--keep-conversations` 保留全部评测会话。

每次真实运行从已持久化会话事件检查：

- 确定性计算先于文字结论，口径不混用，结果未截断；
- 答案只引用当轮真实证据编号，且覆盖经营结果、用户路径、活动成本和目标配置四类核心证据；
- “已确认事实”中每条含数字结论在同行附证据编号；
- 答案分开事实、假设与待验证项，并明确因果边界；
- 下一轮行动写明改变对象、验证指标、护栏指标和停止/继续条件；
- 当目标达成但贡献额下降时，结论不得掩盖这个经营张力；
- 拒绝“持续优化”“加强运营”“提升体验”等空洞建议。
- 结论中的总盘与诊断数字同样需要证据，不允许只在事实附录补引；
- 拒绝没有随机实验或预测模型支撑的无条件增长、下降与改善承诺。
- 初稿未过门禁时最多进行一次证据约束修复；修正版必须通过全部硬门禁才会替换初稿，“分数变高但仍不合格”不会被发布。

## 当前真实运行证据

`representative-suite-run-2026-09-16-v8.json` 记录了当前代码上的 6 条 DeepSeek 端到端代表集：

- 覆盖：字节全链路、腾讯游戏回流、腾讯私域零售，包含目标、成本、路径和方案风险；
- 结果：6/6 场景分别通过 41/41 项硬门禁，无质控补写；
- 路由：每条均先运行确定性总盘，再进行任务约束下的诊断；
- 消耗：12 次模型调用，208,960 tokens，平均 10.527 秒，P95 11.276 秒。

同一代表集此前 `v3` 至 `v7` 的通过数曾在 1/6 到 4/6 之间波动，因此 `v8` 只证明确定性决策契约在一次代表集回归中有效，不代表 54 条矩阵通过率、重复运行稳定性或线上效果。失败历史保留用于回归，不用最好成绩覆盖。

未配置 API Key 时只运行确定性链路与单元测试，不记录或展示虚构的模型通过率。

真实运行完成后，用持久化会话直接评分：

```bash
PYTHONPATH=backend/src .venv/bin/python scripts/score-merchant-trace.py <conversation_id>
```

评分脚本只读取本地 SQLite 中的事件，不会再次调用模型。退出码 `0` 代表全部门槛通过，`1` 代表至少一项未通过；检查明细会以 JSON 输出。
