# 指标与数据口径

## 1. 数据版本

每次导入由四份必需 CSV 与一份可选同期对照面板的内容生成 SHA-256 `snapshot_id`。快照发布后只读；同一轮回答中的关键数字必须来自同一 `snapshot_id` 和 `scope_id`。

`scope_id` 由活动、活动期、对比期、实验组、渠道、经营点、人群和退款口径共同计算。任何字段改变都视为新口径。

## 2. 核心指标

| 指标 | 定义 | 限制 |
|---|---|---|
| 触达用户 | `exposure` 事件的去重 `user_key` | 导入校验保证同一活动用户曝光唯一 |
| 进入用户 | `landing_view` 事件的去重 `user_key` | 进入活动承接页，不推断缺失事件 |
| 权益领取用户 | `offer_claim` 事件的去重 `user_key` | 可映射领券、接受任务或领取资格；不等于核销/完成 |
| 关键行动用户 | `activation` 事件的去重 `user_key` | 由导入方声明为核销、完成任务、有效回流等业务关键行为 |
| 购买用户 | 完成订单的去重 `user_key` | 排除取消订单 |
| 完成订单 | 状态为 completed 的订单数 | 不等于支付尝试数 |
| 客户实付 | 商品金额－商家优惠－平台优惠－退款 | 金额以整数分计算 |
| 净收入 | 商品金额－商家优惠－退款 | 平台优惠不从商家收入再次扣除 |
| 订单贡献额 | 净收入－订单直接成本 | 未扣人力、租金等，不等于净利润 |
| 活动成本 | 成本表中媒体、触达等活动投入之和 | 与订单贡献额分开展示 |
| 贡献/成本 | 实验组订单贡献额 ÷ 活动成本 | 仅用于观察投入效率，不是 ROI 全口径 |

活动主指标在同一 `scope_id` 下确定性判断是否达到 `target_value`。转化率目标用小数（例如 `0.12`），净收入目标用整数分，完成订单用整数，投入产出目标用倍数。

原始事件不能因为名字相近就自动归类。正式接入时需要维护一份版本化映射，例如 `coupon_received → offer_claim`、`mission_accepted → offer_claim`，并由业务负责人确认关键行动定义。当前 CSV 契约只保存映射后的标准节点，这是 MVP 的明确边界。

## 3. 周期比较

默认使用活动期之前的等长窗口作为对比期。若用户修改为不等长周期，结果增加日均比较警告。前后变化属于描述性相关，不能单独证明活动增量。

退款后口径使用 `net_revenue_cents`；退款前口径使用商品金额减商家优惠，并在结果中明确风险。

活动结束后的订单单列为“尾窗观察值”，不并入活动期目标或对比期差额。每笔尾窗订单必须在已确认活动期内找到同一匿名用户、同一实验组、渠道、经营点及人群的先前曝光，且订单时间不超过该匹配曝光后的配置天数。仅同一用户曾在其他标签下曝光，不构成该笔订单的可链接路径。尾窗读数同时列出候选完成订单、纳入订单、未匹配同标签曝光订单和超出曝光后窗口订单，四项之间可核对。这个规则是数据归属约定，不证明活动带来增量；没有导出截至时间时，尾窗 0 单也不等于最终结算为 0。

## 4. 实验判断

二元购买转化使用双侧两比例 z 检验；转化率差的 95% 置信区间使用未合并标准误。任一列联表期望频数小于 5 时标记为小样本，不输出“观察到差异”。

导入契约只能校验曝光唯一，不能验证随机分流、样本比例失配、实验污染或同期干预。因此：

- `p < 0.05` 只表示当前分组中观察到统计差异；
- 它不能单独证明优惠造成了变化；
- 业务决策还需同时检查贡献额、活动成本与长期指标。

下一轮实验样本量规划要求先选择全活动或已完整扫描的具体分组，并明确“购买/曝光”或“激活/领取”作为主指标。后端以该对象、该指标的分母和成功数为基线，采用固定样本、双侧两比例检验、等比例分组，默认 `α=0.05`、检验效能 `80%`。使用者确认最小可检测提升（MDE）和进入实验的流量比例；预计周期按同一目标群体的日均合格用户数推算，流量结构变化后必须重新测算。单店内部按匿名用户随机分流不同体验才适用用户级检验；整店统一动作需要多门店集群设计或仅作为观察性试点。

样本量达到不等于实验可信。上线前还必须确定随机化单元和贡献额护栏阈值，并检查样本比例失配（SRM）、跨组曝光、重复触达与同期干预。上述检查未完成时，方案标记为“待确认”，不得作为扩大决策的充分依据。

## 5. 同期对照增量识别

`incrementality.csv` 是可选输入，不允许用“未曝光用户”临时拼成对照组。每行是一项稳定经营单元在一个周期的结果，字段为 `panel_unit`、`campaign_id`、`period`、`metric`、`treated`、`post`、`outcome` 和 `interference_reviewed`。支持完成订单、购买用户、净收入和贡献额；金额结果仍以整数分表示。

系统只对满足以下条件的面板执行双重差分（DiD）：处理身份跨期不变、所有经营单元拥有相同周期、至少 3 个活动前周期和 1 个活动后周期、处理与对照各至少 4 个单元、同一周期的前后标记一致。估计量是经营单元等权的处理组平均处理效应（ATT）：先对每个单元分别计算活动后周期均值与活动前周期均值的差，再用处理组变化减去对照组变化。这个值是“每个处理经营单元”的平均效应，不是整场活动总增量。主效应和安慰剂检验使用单元变化量的 Welch–Satterthwaite 小样本 t 推断，显式返回有效自由度；前趋势斜率检验使用有限自由度的 Student t 分布，不再用大样本正态近似。

输出因果结论前还必须同时满足：线性前趋势检验未拒绝、末个活动前周期的安慰剂检验未拒绝、导入方确认已审查干扰与外溢。任一检查失败，系统仍展示估计值供排查，但状态为 `validation_failed`，不得把数字解释为活动因果增量。即使全部通过，结论也只在同期对照、稳定构成、平行趋势与无干扰假设下成立，不能外推为全体用户或长期效果。

## 6. 缺失与异常

- 无匹配订单表示证据缺失，不解释为“没有经营”。
- 查询结果被截断时不得使用可见行手工合计。
- 空维度保留为未分组，不静默分配到其他组。
- 所有金额必须非负并以整数分导入；非法日期、重复主键和断裂外键直接拒绝整次导入。
