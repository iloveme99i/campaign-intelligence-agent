# Agent 决策链与安全边界

## 1. 职责分工

确定性系统负责快照校验、查询、聚合、实验统计和证据留存；DeepSeek 负责选择追查路径、解释已计算结果、提出假设与下一轮验证计划。模型不是指标计算器。

```text
选择活动
  → 确认 ReviewScope
  → compare_periods（强制先执行）
  → 判断目标 / 路径 / 实验 / 成本缺口
  → diagnose_dimension（最多选择一个必要维度开始下钻）
  → 形成事实、假设、待验证项
  → 确定性测算下一轮实验样本与周期
  → 持久化 trace 与 evidence_id
```

## 2. 语义化工具

### `compare_periods`

输入冻结的 `ReviewScope`，一次返回活动期/对比期经营结果、实验组漏斗、活动成本和实验统计。它是任何文字结论之前的必经步骤。

### `diagnose_dimension`

仅允许 `variant`、`channel`、`location_id`、`audience` 四个维度。已确认 scope 由服务端绑定，不作为模型参数暴露，模型不能通过工具调用缩窄或改写口径。输出路径节点、转化率、净收入和订单贡献额；实验统计显式标记为 `purchase_per_exposure`。Agent 必须先说明下钻理由，不机械遍历全部维度。

### 受限查询工具

只读快照仍保留 schema、预览和 SELECT 查询能力，用于处理语义化工具未覆盖的问题。读取器拒绝写操作、多语句和超出行数/查询预算的请求。

## 3. 状态与证据

- 用户消息保存 `review_scope`、`scope_id` 和口径来源。
- 工具调用、SQL 结果、文字回答按递增序号分别持久化。
- 每次查询生成不可预测的 `evidence_id`，并附带快照、指标版本、SQL 和绑定参数。
- 页面只渲染结构完整的两期结果；畸形或部分数据不会被补零展示。

页面中的“运行审计”直接复用离线 `score_trace` 的 36 项确定性检查，展示口径、证据、诊断和决策边界是否通过，以及真实模型调用次数、延迟和 token。它不是模型自评或虚构置信度。渠道切片若只存在全活动共享费用，门槛要求回答明确“费用未分摊”，并禁止计算渠道投入效率；路径人数、最低承接节点、实验对照、统计指标血缘、金额单位数量级以及金额与确定性证据的一致性也分别校验。

人机决策不是单向“确认生成内容”。负责人必须在按建议执行、修改后执行和暂不采用之间明确选择；修改与驳回保存结构化原因，修改还保存最终动作。未通过质量门的回答可以被明确驳回并进入失败样本，但不能被采纳或修改后执行。落档事件绑定 Scope ID、回答摘要、负责人、复查日期、实验规划与当时的质量门快照。

“下一轮实验设计”从已持久化的完整扫描读取使用者选择的对象、分组和主指标所对应的分母与成功数，后端计算固定样本量和预计周期。模型不能提交基线数字；MDE、流量比例和业务护栏由使用者确认，避免把生成式建议伪装成实验设计。

“口径修订审计”不依赖模型自述。后端比较最近两个不同且已完成的 `scope_id`，列出活动、日期、渠道、人群等变更及活动期关键指标重算值；新证据形成后，旧结论与旧落档决策的适用性被显式撤销，原始版本仍保留在导出记录中。

## 4. 失败策略

- 未配置模型：完成数据校验和确定性结果，明确提示本机配置 DeepSeek，不伪造 Agent 回答。
- scope 未确认或被模型改写：拒绝查询并返回已确认 scope 标识。
- 查询预算耗尽：停止追查并列出未完成项。
- 无订单或空结果：提示证据缺失，不推断业务为零。
- SSE 中断：运行中的 token 由内存 replay buffer 提供切回重连；工具调用、计算证据、用量与最终完整答案作为耐久事件落库，重复连接不会重复启动同一轮任务。瞬时 token 不逐条落库，避免一轮答案产生上千条消息和历史重组异常。

## 5. 防提示注入

导入数据被声明为不可信资料而不是指令。模型没有写库工具；业务查询由只读连接执行。关键指标在模型调用前完成，降低数据内容改变计算路径或伪造结果的空间。

## 6. 当前技术债

- 通用 SELECT 工具仍比语义化工具权限更宽，企业版应增加字段级策略与查询模板白名单。
- 单机 SQLite 仅适合作品验证；多租户需要身份、行列权限、审计和密钥管理服务。
- 已完成跨电商大促与游戏回流场景的真实 DeepSeek 开发验收并保留失败回归，但样本量不足以声明稳定工具选择通过率；详见 `evals/real-runs-2026-09-11.json`。
