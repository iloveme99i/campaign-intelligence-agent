# 产品需求简报：Campaign Intelligence

## 1. 问题与用户

目标用户是连锁零售与本地生活商家的用户运营、增长运营和产品经理。一次活动结束后，他们需要回答四个相互关联的问题：目标是否达成、变化发生在哪个用户路径节点、实验组多出来的转化是否值得成本、下一轮先改什么。

当前项目没有真实用户访谈或企业后台数据。需求依据是目标岗位 JD 中反复出现的活动复盘、trace 路径分析、A/B 测试和迭代策略职责，以及公开业务流程形成的待验证假设。以下内容不能被表述成已验证的用户事实。

## 2. 当前工作流假设

常规报表把交易、行为和成本分开呈现，使用者需要手动对口径、拼表并解释异常。通用问数 Agent 又容易在口径未确认时直接生成结论，或把模型推断写成事实。

本产品将流程固定为：

1. 导入活动配置、匿名行为事件、完成订单和活动成本；具备稳定同期经营单元时可另行导入增量面板。
2. 先选择要支持的决策、优先风险并补充已知业务限制；系统将其保存为带 `task_id` 的结构化复盘任务。
3. 选择活动并确认活动期、等长对比期、人群、渠道、经营点与退款口径。
4. 确定性工具先计算目标、路径、实验和成本证据。
5. Agent 结合决策任务与业务限制选择一个必要维度下钻，记录选择理由和独立证据；证据足够后停止扩展查询。
6. 负责人将行动、复查日期与当前证据口径绑定；口径改变后生成新 `scope_id`，不覆写旧记录。

## 3. 核心使用场景

### 场景 A：活动目标复核

运营选择活动后，系统展示活动期和对比期的完成订单、净收入、商家优惠与订单贡献额。所有数字必须来自同一快照和同一口径。

### 场景 B：路径问题定位

目标未达成时，Agent 从触达、进入、权益领取/任务接受、关键行为到交易定位变化节点；只有总盘出现具体缺口，才下钻渠道、人群、经营点或实验组。标准化节点允许不同活动复用一套证据链，但导入方必须声明原始事件到标准节点的映射。

### 场景 C：实验收益与代价

系统比较实验组转化率、95% 置信区间、活动成本和贡献/成本，同时提示随机分流无法由导入文件验证，不将显著差异直接解释为因果。若另有活动级同期经营单元面板，则独立执行平衡面板 DiD、前趋势、活动前安慰剂与干扰审查；验证失败只展示诊断，不输出因果增量。筛选子群或修改活动日期后，不复用全活动面板估计。

### 场景 D：口径纠正

用户修改日期或筛选条件后，系统重新计算并保留新证据，Agent 说明哪些旧结论失效。

## 4. 非目标

- 不生成活动创意、营销文案或商家经营口号。
- 不代替数据仓库、CRM、投放平台或权限系统。
- 不允许模型修改业务数据，也不允许模型心算关键指标。
- 不用合成示例宣称真实收益、真实用户或线上实验结果。
- 当前不处理姓名、手机号等直接身份信息。

## 5. MVP 验收标准

- 四份必需 CSV 与可选同期对照面板能被严格校验并生成不可变快照。
- 用户在回答前能看到并修改完整复盘口径。
- 目标、漏斗、实验与成本数据能回溯到真实 `evidence_id`。
- Agent 只能在已确认口径下使用语义化复盘工具，查询存在预算上限。
- 结构化任务必须触发一次有理由、同口径且与任务匹配的定向诊断；无目的遍历维度不通过。
- 口径混用、结果截断、虚构证据、缺失因果边界任一发生时，评测不通过。
- 桌面与 320px 移动视口均可完成活动选择、口径确认和结果阅读。

## 6. 待验证事项

- 商家实际可提供的数据字段与更新频率。
- 使用者最常纠正的口径，以及可接受的确认成本。
- 运营更需要“自动下钻”还是“推荐后确认下钻”。
- 贡献额口径是否需要接入额外履约、门店或会员成本。
- 真实 DeepSeek 调用的工具选择稳定性、延迟与单位复盘成本。
